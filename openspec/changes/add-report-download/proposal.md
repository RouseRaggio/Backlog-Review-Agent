# Proposal: Add HTML Report Download to Backlog Review Agent

## Problem Statement
After running a backlog audit through the React dashboard, users need to download the full HTML audit report generated by `HtmlReportGenerator` for sharing, archiving, or offline consultation. Currently, the report is only written to the server's filesystem under `reports/latest/{PROJECT}_AUDIT.html` without a direct download mechanism from the web UI.

## Proposed Solution
1. **API Endpoint (`GET /api/reviews/{project_key}/report`)**:
   - Securely serves the generated HTML report file from `reports/latest/{project_key}_AUDIT.html` using FastAPI's `FileResponse` with `media_type="text/html"` and `Content-Disposition: attachment; filename="{PROJECT}_AUDIT.html"`.
   - Validates `project_key` strictly to prevent directory traversal or arbitrary file access.
   - Responds with HTTP 200 for valid existing reports, HTTP 404 if not found, and HTTP 400 for malformed project keys.
2. **Immediate Generation in `POST /api/reviews`**:
   - Ensures `HtmlReportGenerator().generate(report)` is called immediately after `AuditBacklogUseCase.execute()` so the HTML file is created in `reports/latest/` upon review completion.
3. **Frontend Download Action**:
   - Adds a dedicated `downloadReport(projectKey)` helper in `src/services/api.ts` that triggers an asynchronous Blob download.
   - Integrates a "Descargar reporte HTML" button in the React Dashboard with loading, success, and error feedback states.

## Assumptions & Boundaries
- Uses the existing storage pattern (`reports/latest/{PROJECT}_AUDIT.html`) without adding a database or fake review IDs.
- Future audit history and review tracking remain out of scope for this change.
- Existing CLI, Clean Architecture, and Docker volume persistence (`./reports:/app/reports`) remain intact.

## Success Criteria
- Executing an audit from the web UI generates the corresponding HTML report under `reports/latest/`.
- Clicking "Descargar reporte HTML" downloads `{PROJECT}_AUDIT.html` in the browser without full-page reloads.
- Requests with path traversal attempts or invalid project keys return HTTP 400.
- Non-existent reports return HTTP 404.
