## ADDED Requirements

### Requirement: AIReviewEngine orchestrator

The system SHALL provide an `AIReviewEngine` class in the application layer that orchestrates the end-to-end lifecycle of an AI capability execution.

The `AIReviewEngine` SHALL:
1. Maintain a registry of `AICapability` instances (id → AICapability mapping)
2. Accept a pre-configured `AIProvider` instance (already wrapped with retry and rate limiting by infrastructure)
3. Accept a `PromptRenderer` instance for template rendering
4. Accept a correlation ID generator (callable returning a unique string per report run)
5. Execute a capability by: loading its prompt template → rendering with input params → calling the provider → validating output against schema → returning the parsed output

The constructor SHALL accept:

```python
@dataclass
class AIReviewEngine:
    provider: AIProvider
    prompt_renderer: PromptRenderer
    prompt_loader: PromptLoader       # infrastructure service that reads prompt files
    capabilities: dict[str, AICapability]
    config: AiConfig
    correlation_id: str
    logger: Logger                    # application logger
```

`PromptLoader` SHALL be an infrastructure service with a single method:
- `load(capability_id: str, prompt_dir: str) -> str` — reads the prompt template file from disk and returns its content as a string
- Raise `FileNotFoundError` if the file does not exist at `{prompt_dir}/{capability_id}.txt`

#### Scenario: AIReviewEngine can be constructed

- **WHEN** an `AIReviewEngine` is created with all dependencies
- **THEN** it SHALL have a `capabilities` dict populated with the registered capabilities

#### Scenario: PromptLoader loads template from disk

- **WHEN** `prompt_loader.load("executive_summary", "prompts")` is called
- **THEN** it SHALL return the content of `prompts/executive_summary.txt`
- **AND** raise `FileNotFoundError` if the file does not exist

### Requirement: Executing a capability

The `AIReviewEngine` SHALL provide an `execute(capability_id: str, input_data: dict) -> AICapabilityOutput | None` method.

The execution flow SHALL be:

1. Look up the capability in the registry by `capability_id`
2. Look up capability-specific config (`CapabilityConfig`) from `AiConfig.capabilities`, falling back to global defaults
3. Load the prompt template file via `PromptLoader`
4. Render the template with `input_data` via `PromptRenderer`
5. Determine the model to use: capability-level override if set, otherwise provider default
6. Call `provider.generate(prompt, model=model, max_tokens=..., temperature=...)`
7. Parse and validate the response against the capability's `output_schema`
8. Return the validated output
9. On any failure (prompt not found, provider error, parsing error, validation error), log the error with correlation ID and return `None`

If the `capability_id` is not found in the registry, `execute()` SHALL raise a `ValueError`.

#### Scenario: Capability executed successfully

- **WHEN** `execute("executive_summary", {"score": 72, "fail_count": 5})` is called
- **AND** all steps succeed
- **THEN** it SHALL return an `AICapabilityOutput` subclass matching the registered schema

#### Scenario: Unknown capability raises ValueError

- **WHEN** `execute("nonexistent", {})` is called
- **THEN** it SHALL raise a `ValueError` with the unknown capability id

#### Scenario: Provider failure returns None

- **WHEN** the provider raises an exception
- **THEN** the engine SHALL log the error with correlation ID
- **AND** return `None`

#### Scenario: Validation failure returns None

- **WHEN** the LLM response fails schema validation
- **THEN** the engine SHALL log the `SchemaValidationError` with correlation ID
- **AND** return `None`

### Requirement: Capability-specific model and temperature

The engine SHALL resolve the model and temperature for each capability execution using the following order (first match wins):

1. `CapabilityConfig` from `AiConfig.capabilities[capability_id]` (model, temperature, max_tokens)
2. Global `AiConfig` defaults (model, temperature, max_tokens)
3. Provider's `default_model` if no model is configured

#### Scenario: Capability config overrides global

- **WHEN** `AiConfig.capabilities["executive_summary"].model` is `"gpt-4"`
- **AND** `AiConfig.model` is `None`
- **THEN** the engine SHALL call `provider.generate()` with `model="gpt-4"`

#### Scenario: Fallback to provider default

- **WHEN** no model is configured at any level
- **THEN** the engine SHALL call `provider.generate()` with no model argument, letting the provider use its `default_model`

### Requirement: Correlation ID flow

The correlation ID SHALL be generated once at the start of each `AuditBacklogUseCase.execute()` call and passed through all AI operations.

The correlation ID SHALL be a 12-character hex string generated by `uuid.uuid4().hex[:12]`.

The `AIReviewEngine` SHALL accept the correlation ID at construction time and include it in every log message and every provider call.

#### Scenario: Correlation ID appears in logs

- **WHEN** any AI event is logged
- **THEN** the log entry SHALL include the correlation ID

### Requirement: AIReviewEngine is optional in AuditBacklogUseCase

The `AuditBacklogUseCase` SHALL accept an optional `AIReviewEngine` instance in its constructor, defaulting to `None`.

When `AIReviewEngine` is `None`, no AI analysis SHALL occur and the report SHALL be returned without `ai_summary`.

When `AIReviewEngine` is provided, the use case SHALL:
1. Generate a correlation ID
2. Call `engine.execute("executive_summary", report_data)`
3. If the result is not `None`, assign it to `report.ai_summary`
4. If the result is `None`, leave `report.ai_summary` as `None`

#### Scenario: AIReviewEngine provided — summary attached

- **WHEN** `AuditBacklogUseCase` has an `AIReviewEngine`
- **AND** the engine returns a valid output
- **THEN** `report.ai_summary` SHALL contain the output

#### Scenario: AIReviewEngine not provided — no AI

- **WHEN** `AuditBacklogUseCase` has no `AIReviewEngine`
- **THEN** no AI calls SHALL be made
- **AND** `report.ai_summary` SHALL be `None`

### Requirement: Bootstrap wiring sequence

The `build_application()` function in `src/bootstrap/dependency_injection.py` SHALL execute the following sequence when AI is enabled:

1. Load `AppConfig` via `ConfigLoader.load()`
2. If `config.ai.enabled` is `False`, skip all AI initialization
3. Create provider-specific config dataclass based on `config.ai.provider`
4. Create the `AIProvider` instance via `AIProviderFactory.create(config.ai.provider, provider_config)`
5. Call `provider.health()`:
   - If health check fails, log warning, set `config.ai.enabled = False`, skip remaining steps
6. Wrap the provider with retry logic (infrastructure decorator or wrapper class)
7. Wrap the provider with rate limiter (infrastructure decorator or wrapper class)
8. Create `PromptLoader` (infrastructure, reads prompt files from `config.ai.prompt_dir`)
9. Create `PromptRenderer` (domain, no external dependencies)
10. Register capabilities in a dict, each with its prompt template name and output schema class
11. Generate initial correlation ID
12. Create `AIReviewEngine` with all dependencies
13. Pass `AIReviewEngine` to `AuditBacklogUseCase`

If any step in steps 4-6 fails, the system SHALL log the error and continue without AI (set `AIReviewEngine` to `None`).

#### Scenario: Full AI bootstrap succeeds

- **WHEN** all bootstrap steps complete without error
- **THEN** `AuditBacklogUseCase` SHALL have a configured `AIReviewEngine`

#### Scenario: Health check fails at bootstrap

- **WHEN** `provider.health()` returns `HealthStatus(reachable=False, auth_valid=False, model_accessible=False)`
- **THEN** the system SHALL log the health failure
- **AND** set `AIReviewEngine` to `None`
- **AND** continue report generation without AI

#### Scenario: AI disabled — no initialization

- **WHEN** `config.ai.enabled` is `False`
- **THEN** no AI provider, health check, or engine SHALL be created
- **AND** `AuditBacklogUseCase` SHALL have `AIReviewEngine` set to `None`
