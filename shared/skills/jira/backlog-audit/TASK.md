# Task Audit Standard

**Skill:** Backlog Audit

**Versión:** 1.0.0

**Tipo de Issue:** Task

---

# Objetivo

Definir el estándar organizacional para auditar Tasks en Jira.

Una Task representa una unidad de trabajo técnico o funcional que debe estar claramente definida antes de iniciar su ejecución.

---

# Información Obligatoria

## Identificador

Debe existir un identificador único.

---

## Resumen

Debe describir claramente el trabajo a realizar.

No debe ser ambiguo.

Debe ser comprensible para cualquier miembro del equipo.

---

## Descripción

Toda Task debe poseer una descripción.

La descripción deberá responder:

- ¿Qué debe hacerse?
- ¿Por qué debe hacerse?
- ¿Cuál es el resultado esperado?

---

# Responsable

Cuando aplique deberá existir un responsable asignado.

---

# Prioridad

Debe existir una prioridad válida.

---

# Estimación

Debe poseer una estimación cuando el proceso organizacional lo requiera.

---

# Epic

Cuando aplique deberá estar asociada a una Epic.

---

# Sprint

Cuando pertenezca a un Sprint deberá verificarse que esté correctamente planificada.

---

# Dependencias

Las dependencias deberán documentarse.

---

# Riesgos

Cuando existan deberán registrarse.

---

# Hallazgos

La auditoría deberá detectar como mínimo:

- Task sin descripción.
- Task ambigua.
- Task sin prioridad.
- Task sin responsable.
- Task sin estimación.
- Task sin Epic cuando aplique.
- Task duplicada.

---

# Definition of Ready

Una Task estará lista cuando:

- Tiene título.
- Tiene descripción.
- Tiene prioridad.
- Tiene responsable.
- Tiene estimación.
- Tiene contexto suficiente.
- Puede ejecutarse sin solicitar información adicional.

---

# Estado Final

- READY
- NEEDS REVIEW
- NEEDS REFINEMENT
- BLOCKED
