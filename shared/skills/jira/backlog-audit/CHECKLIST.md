# Backlog Audit Checklist

**Skill:** Backlog Audit

**Versión:** 1.0.0

---

# Objetivo

Este checklist define los criterios mínimos que debe verificar la Skill durante una auditoría de Backlog.

El incumplimiento de uno o más criterios deberá generar un hallazgo con su respectiva severidad y recomendación.

---

# Reglas Generales

Cada criterio deberá producir uno de los siguientes resultados:

- ✅ Cumple
- ⚠️ Advertencia
- ❌ No Cumple
- N/A No Aplica

Cada incumplimiento deberá incluir:

- Descripción del problema.
- Severidad.
- Recomendación.
- Referencia al criterio evaluado.

---

# 1. Información General

## 1.1 Identificador

- [ ] El Issue posee un identificador válido.
- [ ] tiene fecha de entrega



---

## 1.2 Resumen

- [ ] Existe un título.

- [ ] El título describe claramente el objetivo.

- [ ] No contiene información ambigua.

---

## 1.3 Descripción

- [ ] Existe descripción.

- [ ] La descripción es clara.

- [ ] La descripción es suficiente.

- [ ] No contiene información contradictoria.

---

# 2. Historia de Usuario (cuando aplique)

## Formato

- [ ] Contiene "Como"

- [ ] Contiene "Quiero"

- [ ] Contiene "Para"

---

## Calidad

- [ ] Es comprensible.

- [ ] Describe una necesidad del usuario.

- [ ] Explica el beneficio esperado.

---

# 3. Criterios de Aceptación

- [ ] Existen criterios.

- [ ] Son verificables.

- [ ] Son medibles.

- [ ] No son ambiguos.

- [ ] Cubren el comportamiento esperado.

---

# 4. Reglas de Negocio

- [ ] Existen reglas de negocio.

- [ ] Son claras.

- [ ] Son suficientes.

---

# 5. Aspectos Funcionales

- [ ] Se describen correctamente.

- [ ] No existen vacíos funcionales.

---

# 6. Aspectos No Funcionales

Verificar si existen cuando sean requeridos.

- [ ] Rendimiento

- [ ] Seguridad

- [ ] Disponibilidad

- [ ] Accesibilidad

- [ ] Escalabilidad

- [ ] Compatibilidad

---

# 7. Priorización

- [ ] Tiene prioridad.

- [ ] La prioridad es válida.

- [ ] La prioridad corresponde al negocio.

---

# 8. Estimación

- [ ] Posee estimación.

- [ ] La estimación es válida.

- [ ] La historia es estimable.

---

# 9. Epic

Cuando aplique.

- [ ] Está asociada a una Epic.

- [ ] La Epic existe.

---

# 10. Sprint

Cuando aplique.

- [ ] Pertenece al Sprint correcto.

---

# 11. Dependencias

- [ ] Existen dependencias documentadas.

- [ ] Las dependencias son claras.

---

# 12. Riesgos

- [ ] Los riesgos fueron identificados.

- [ ] Los riesgos fueron documentados.

---

# 13. Responsable

- [ ] Existe responsable.

---

# 14. Etiquetas

- [ ] Posee etiquetas.

- [ ] Las etiquetas siguen el estándar organizacional.

---

# 15. Estado

- [ ] El estado del Issue es consistente con el flujo del proyecto.

---

# 16. Calidad General

Evaluar:

- [ ] Claridad

- [ ] Completitud

- [ ] Consistencia

- [ ] Trazabilidad

- [ ] Estimabilidad

- [ ] Mantenibilidad

---

# 17. Hallazgos

Para cada incumplimiento registrar:

- Criterio.
- Descripción.
- Severidad.
- Recomendación.

---

# 18. Backlog Quality Score

Calcular el puntaje general considerando todos los criterios evaluados.

---

# 19. Estado Final

Seleccionar uno:

- [ ] READY

- [ ] NEEDS REVIEW

- [ ] NEEDS REFINEMENT

- [ ] BLOCKED

---

# Resultado Esperado

Una auditoría se considera completa cuando:

- Todos los criterios aplicables fueron evaluados.
- Todos los hallazgos fueron registrados.
- Cada hallazgo posee una recomendación.
- Se calculó el Backlog Quality Score.
- Se asignó un Estado Final al Issue.
